## Why schema 84, not 78 or 83
The owner and commercial branches used overlapping migration numbers for different features. Schema 84 combines their actual structures and records feature migrations; it does not merely relabel a schema.
Synthetic databases generated by the original DB78 and DB83 source commits are included under test/fixtures/migration. Tests check financial-row preservation, required structures, integrity, restart idempotence and refusal to downgrade a future schema. They contain no customer data.
These tests do not replace a backup and acceptance test on a COPY of a particular customer's database.

## Safety and release boundaries
Owner builds explicitly enable YALLA_OWNER_LOCAL_FULL_ACCESS; customer authentication keeps its default behavior. Owner packages must never be distributed to customers.
The warning marker AUTH_BYPASS_ACTIVE_DO_NOT_RELEASE.txt is retained as a packaging caution, not as proof of a production acceptance pass. Android owner APKs use debug signing; iPhone owner packages are unsigned unless separately signed.
No production database, customer photos, production defines, signing keys or device activation data are included in the source archive or application packages. Git history, input backups and evidence are private and must not be distributed as the application.
Windows storage-location behavior and each mobile platform's sandbox behavior are preserved. Moving the SOURCE does not move live data.
No live databases or Yalla Control deployments were modified during consolidation.
