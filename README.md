خطة YALLA ACCOUNTS الشاملة – النسخة النهائية
المرحلة 1 — قسم إصلاح المركبات (Repairs)

القسم الأساسي للورش، ويجب إنهاؤه أولاً لأنه المصدر الرئيسي للفواتير والإيرادات.

1.1 نموذج إدخال/تعديل/تفاصيل الإصلاح

ضبط جميع الحقول: بيانات المركبة – المستفيد – العمل – الحالة – المالية – الملاحظات.

دعم:

كشف القطع مع الأسعار.

كشف الأعمال مع الأسعار.

الحساب التلقائي للإجمالي (قيمة الملف).

دعم إضافة الصور من الكاميرا والمعرض.

دعم تعديل/حذف الصور مع حذفها من التخزين.

عرض الصور بالحجم الكامل داخل Details.

1.2 شاشة إصلاح المركبات (RepairsScreen – النسخة الاحترافية)

تصميم يتناسب مع YALLA:

AppBar + شعار.

عرض بطاقات / جدول متجاوب (موبايل + كمبيوتر).

ترتيب: أحدث ملف بالأعلى.

أدوات إدارة:

بحث نصي.

فلترة حسب التاريخ.

فلترة حسب الحالة.

فلترة حسب المستفيد (أفراد/تأمين).

زر إضافة مركبة جديد (FAB).

1.3 الأرشفة + المتابعة مع التأمين

إضافة حقل: is_archived أو status إضافي.

فلتر "إظهار الأرشيف" / "السجلات النشطة".

إضافة عمود "متابعة التأمين":

تم تسليم الفاتورة

تم التسديد في التعويضات

تم التسديد في المالية

تم الصرف

يظهر فقط إذا المستفيد شركة تأمين.

1.4 تصدير PDF + Excel لملف الإصلاح

PDF يحتوي:

رأس الصفحة مع الشعار والبيانات.

جدول القطع + جدول الأعمال.

الحساب التلقائي للإجمالي.

التاريخ بالإنجليزي (yyyy-MM-dd).

تصدير عدة ملفات:

فقط الملفات الظاهرة بعد الفلترة.

مجموع قيم الإصلاحات في أسفل التقرير.

Excel مطابق للفلاتر.

1.5 الإشعارات (Reminders)

تنبيهات للملفات:

غير المسددة.

المتأخرة.

المستحقة خلال X يوم.

بطاقة إنذار صغيرة داخل RepairsScreen.

المرحلة 2 — الموردون والمشتريات (Suppliers & Purchases)
2.1 قسم الموردين (Suppliers)

جدول suppliers كامل: pid, name, phone, address, isActive.

شاشات:

SuppliersListScreen (بحث، فلترة، تفعيل/تعطيل).

SupplierAddScreen / EditScreen.

ربط الموردين بالـ GL عبر subaccounts:

2200.S<supplierPid>

2.2 قسم المشتريات (Purchases)

PurchasesListScreen (فلترة، بحث، PDF، Excel).

PurchaseAddScreen:

اختيار مورد.

إضافة purchase_lines:

نوع المادة (RAW/PARTS/TOOLS/OTHER).

الكمية، السعر، المجموع.

طريقة الدفع:

نقدي – بنك – على الحساب – جزئي.

حالة الفاتورة.

PurchaseEditScreen كاملة.

2.3 ربط المشتريات مع GL

عند حفظ فاتورة:

Dr 1400 (مخزون)

Cr 2200.S<supplierPid> أو Cr 1000/1010

عند الدفع للمورد:

Dr 2200.S

Cr 1000/1010

عند التعديل/الحذف:

عكس القيد القديم.

إنشاء قيد جديد.

ربط كل GL line بـ purchase_id.

2.4 تقارير المشتريات

تقرير مشتريات حسب:

الفترة

المورد

نوع المادة

كشف حساب مورد

تقرير أعمار الديون (Supplier Aging)

PDF + Excel.

المرحلة 3 — العملاء (Customers) + الفواتير + الذمم المدينة (AR)
3.1 قسم العملاء (Customers)

جدول customers:

id, name, type (individual/insurance), phone, address, isActive.

شاشات:

CustomersListScreen

CustomerAdd / CustomerEdit

3.2 الربط مع إصلاح المركبات والفواتير

في AddRepair:

إذا "أفراد" → اختيار/إضافة من customers.

إذا "تأمين" → اختيار من customers type=insurance.

إضافة customer_id لجدول repairs (إن لم يكن مضافًا).

إنشاء فاتورة تلقائية/يدوية لكل ملف إصلاح.

3.3 ربط العملاء مع GL (Accounts Receivable)

عند اعتماد ملف إصلاح:

Dr 1200.C<customerId>

Cr 4000 (إيرادات)

عند استلام دفعة من العميل:

Dr 1000/1010

Cr 1200.C<customerId>

3.4 تقارير العملاء

كشف حساب عميل.

أعمار الديون (AR Aging).

PDF + Excel.
